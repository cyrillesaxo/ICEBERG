# UI Iceberg v0.7.2 - Research Basis

## Purpose
v0.7.2 is a mature-testing-primitive integration release. It does not treat competitor products as normative authorities. It extracts operational atoms that have survived substantial practical use, generalizes them into vendor-neutral PackSpec primitives, and places each under UI Iceberg oracle licensing, antiwitness, TERM and authority controls.

## Competitive primitive evidence
- Playwright actionability/auto-waiting checks unique resolution, visibility, stability, event reception, enabled state and editability before relevant actions. UI Iceberg generalizes this into `InteractionReadinessVector`; it does not copy Playwright implementation details. https://playwright.dev/docs/actionability
- Playwright recommends resilient user-facing locators such as role, label and text, while noting explicit test IDs as a separate contract. UI Iceberg generalizes this into `SemanticTargetIdentity`, separating user/task meaning from implementation selectors. https://playwright.dev/docs/locators
- Storybook defines a story as a rendered state of a UI component and encourages multiple stories for interesting supported states. UI Iceberg generalizes this into `StateManifest + StateMissSet`; undeclared required states remain explicit coverage debt. https://storybook.js.org/docs/get-started/whats-a-story
- Cypress UI Coverage computes tested interactive elements over observed interactive elements and exposes untested UI surface. UI Iceberg imports the surface-coverage primitive but forbids promoting it to task, semantic, cognitive or human convergence. https://docs.cypress.io/ui-coverage/core-concepts/interactivity
- Cypress retries are explicitly designed to detect/cope with flaky tests caused by races, network and other unpredictable conditions. UI Iceberg preserves attempt history and classifies retry-dependent success as `FLAKY_PASS`, not stable PASS. https://docs.cypress.io/app/guides/test-retries
- Chromatic TurboSnap uses Git changes plus a dependency graph to select affected stories/snapshots. UI Iceberg generalizes the dependency-impact idea into `ReactivationImpactGraph` for primitives, invariants, witnesses, baselines and TERM receipts, with conservative expansion when impact is uncertain. https://www.chromatic.com/docs/turbosnap/
- Applitools supports different visual comparison treatment for regions, including layout-oriented and ignored regions. UI Iceberg generalizes this into `VisualOracleRegionPolicy`, but requires semantic owner, claim, authority, expiry and residual risk for dynamic/ignored regions. https://help.applitools.com/hc/en-us/articles/360007188151-Match-Regions
- FullStory surfaces field frustration signals including rage clicks, dead clicks, error clicks and cursor thrashing, while its own guidance notes some signals can be triggered by intended behavior. UI Iceberg uses them as `BehavioralFrictionWitness` observations that promote hypotheses rather than proving user intent or root cause. https://help.fullstory.com/hc/en-us/articles/360020624154-Rage-Clicks-Error-Clicks-Dead-Clicks-and-Thrashed-Cursor-Frustration-Signals
- mabl auto-heal can search for similar elements; mabl emphasizes assertions, confidence and review because healing can target the wrong element. UI Iceberg generalizes this into `LocatorSubstitutionProposal` plus `TestMutationReceipt`, where semantic identity must be independently supported. https://help.mabl.com/hc/en-us/articles/19078158616340-Assertions-and-auto-heal and https://help.mabl.com/hc/en-us/articles/19078583792404-How-auto-heal-works

## Epistemic posture
These sources support operational primitive extraction only. They do not license universal thresholds, prove UI Iceberg superiority, establish project intent, or replace WCAG/domain/product authority. Vendor-specific algorithms, heuristics and proprietary implementations are not copied. The PackSpec retains the generic test atom, its evidentiary function and its known failure mode.
