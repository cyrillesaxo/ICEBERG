Find what your UI tests forgot to test.

UI Iceberg is open-source UI journey assurance and test-scenario intelligence. It helps developers, QA teams, and AI coding agents identify important journey scenarios, missing states, recovery paths, and the difference between evidence that passed and coverage that is still unknown.

View UI Iceberg on GitHub

What UI Iceberg does

What should I test?
Generate a prioritized, bounded scenario plan for a critical UI journey.
What am I missing?
Map existing tests against important journey states and recovery paths.
What actually ran?
Reconcile Playwright runtime evidence without turning retries or vague matches into false PASS.

Why teams use it

Browser automation tools are good at executing tests. UI Iceberg focuses on the upstream and cross-cutting problem: scenario design, unknown coverage, and evidence boundaries. A team can have hundreds of green UI tests while still missing OTP return flows, session expiry, duplicate submits, recovery after request failure, state loss after refresh, or important human assumptions that automation did not verify.

For AI coding agents

UI Iceberg includes an experimental MCP server for tools such as Cursor, Codex, Bolt, and other coding agents. The coding agent remains the builder. Playwright remains the browser executor. UI Iceberg provides an independent scenario and evidence model so the same agent does not silently define both implementation and proof.

Common questions

Is UI Iceberg another Selenium, Playwright, Cypress, or Katalon replacement?

No. It is designed to work with those tools. They execute or manage tests; UI Iceberg helps determine which journey conditions deserve evidence and which important conditions remain unverified.

How is UI Iceberg different from asking an AI to generate edge cases?

A generic AI can create a useful checklist. UI Iceberg aims to maintain a persistent, bounded scenario model tied to repository evidence, stable scenario identifiers, runtime results, explicit gaps, and later change revalidation.

What does “unknown coverage” mean?

An important journey condition has not been sufficiently verified. UI Iceberg deliberately treats unknown as different from pass.

Is UI Iceberg production-ready?

Version 0.2 is experimental. Scenario planning, candidate test mapping, Playwright scaffold generation, and Playwright JSON runtime reconciliation are implemented. The project does not yet claim complete journey certification.
